# Galaxy Classifier — описание проекта

Учебный pet-проект. Веб-сервис на FastAPI с ML-моделью классификации изображений галактик.

## 1. Цель проекта

Разработать веб-сервис, который принимает от пользователя фотографию галактики и возвращает предсказанный морфологический тип (один из 10 классов) вместе с оценкой уверенности модели. Проект объединяет backend-разработку (REST API, база данных, авторизация) и прикладное машинное обучение (обучение и инференс классификатора изображений на PyTorch).

## 2. Что считаем итогом проекта

К моменту сдачи должно быть реализовано:

- Рабочий REST API (FastAPI) с эндпоинтом загрузки изображения и получения предсказания.
- Хранение истории предсказаний в базе данных (PostgreSQL) с привязкой к пользователю (для авторизованных) или анонимно.
- Регистрация и вход пользователей (JWT-авторизация, хеширование паролей через Argon2).
- Эндпоинт просмотра пользователем собственной истории запросов.
- Расширенные права для роли «администратор» (просмотр данных всех пользователей).
- Обученная модель (PyTorch, CNN) с задокументированной точностью на тестовой выборке и хотя бы одной экспериментальной попыткой её повышения (см. раздел 4).
- Миграции схемы БД (Alembic), воспроизводимое окружение (Docker для БД), базовая обработка ошибок и валидация входных данных (формат/размер изображения).

Проект не нацелен на production-уровень нагрузки — это учебная демонстрация полного цикла: от сырых данных и обучения модели до работающего API, который ими пользуется.

## 3. Стек и архитектура

- **Backend:** FastAPI (синхронный режим — осознанный выбор: async даёт выигрыш только при высокой конкурентной нагрузке на БД, которой в pet-проекте нет).
- **База данных:** PostgreSQL в Docker, SQLAlchemy 2.0 (Mapped/mapped\_column), Alembic для миграций.
- **Авторизация:** JWT (PyJWT), хеширование паролей — Argon2 (argon2-cffi).
- **ML:** PyTorch, собственная CNN-архитектура (2 свёрточных слоя), обучена на датасете Galaxy10 DECals (10 классов, \~16 тыс. изображений).
- **Обработка изображений:** Pillow + OpenCV (валидация, препроцессинг, сжатие для хранения).

## 4. Направления развития и способы их реализации

### 4.1 Backend-функциональность

| Аспект | Как реализуем |
| --- | --- |
| Регистрация и вход | JWT access-токен (срок жизни 24 часа), пароли хешируются Argon2, email как логин |
| История предсказаний | Эндпоинт `GET /predictions/me`, фильтрация по `user_id` из токена |
| Роль администратора | Отдельная зависимость FastAPI, проверяющая роль пользователя в БД (не в токене — чтобы изменение роли или блокировка пользователя действовали мгновенно, а не только после истечения токена); админ-эндпоинты для просмотра всех предсказаний/пользователей |
| Анонимный доступ | Эндпоинт загрузки изображения остаётся доступен без авторизации; `user_id` в таблице предсказаний nullable |

### 4.2 Повышение точности модели — экспериментальные направления

Текущая модель (простая CNN, вход 64×64) показывает точность около 60% на тестовой выборке. Это заведомо базовый результат, и далее планируется экспериментально проверить, что даёт наибольший прирост:

1. **Увеличение разрешения входного изображения (64×64 → 128×128).** Гипотеза: на 64×64 теряются мелкие структурные детали (спиральные рукава, перемычки), из-за чего модель путает похожие классы и принимает шумовые артефакты (яркие блики, соседние объекты на кадре) за часть галактики. Проверено практически: конкретный случай с ярким бликом на фото, из-за которого модель ошибочно классифицировала одиночную галактику как «сливающиеся галактики». Увеличение разрешения потребует пересборки обучающего датасета и пересчёта архитектуры полносвязного слоя под новый размер входа.
2. **Архитектурные изменения CNN.** Текущая архитектура — 2 свёрточных слоя без регуляризации (Dropout, BatchNorm). Планируется попробовать добавить BatchNorm и Dropout для борьбы с переобучением, особенно при переходе на 128×128 (рост числа параметров полносвязного слоя).
3. **Согласованность препроцессинга между обучением и инференсом.** Уже устранена одна найденная проблема: на этапе обучения и в API использовались разные методы интерполяции при сжатии изображений (LANCZOS4 против AREA), что создавало расхождение между данными, на которых модель обучалась, и данными, которые она видит в проде. Приведено к единому методу.
4. **Сбор дополнительных размеченных данных от пользователей (опционально, если останется время).** Идея: дать пользователю возможность указать, что предсказание неверное, и выбрать правильный класс. Эти исправления логируются в отдельную таблицу и могут быть использованы как дополнительный размеченный датасет для дообучения модели в будущем (в виде отдельного оффлайн-переобучения, не «обучения в реальном времени» — это отдельно обсуждался и признан избыточным по рискам для объёма проекта).

По каждому эксперименту будет зафиксирован результат (точность до/после на одной и той же тестовой выборке).
